## Claims that need a different interpretation

- The reported `$6,000/month` loss, `37/100` health score, price, conversion-lift percentages, and performance guarantee have no supporting traffic, attribution, lead, or sales data in the supplied report. They are not measured business outcomes.
- Edge caching already exists: three live requests returned `X-Vercel-Cache: HIT`. Observed response-header times from this machine were 296, 58, and 78 ms, including connection effects. These are samples, not global TTFB or field Core Web Vitals. The original single 900 ms observation does not establish an origin bottleneck.
- GA4 absence does not establish the absence of all analytics. This checkout contains Vercel Analytics. The live `/_vercel/insights/script.js` endpoint returned HTTP 200, but the observed browser visit did not request it. Collection, dashboard availability, and production integration remain unverified. A raw HTML substring detector would also miss scripts injected after hydration.
- No paid advertising pixels or session replay were added. They require actual marketing accounts, measurement goals, and appropriate visitor controls; absence alone is not a security vulnerability or quantified revenue leak.
- Structured data describes the real person and website. No reviews, product ratings, or other unsupported entities were invented. Search-result enhancements are not guaranteed.

## Additional findings and fixes

1. **Outdated framework and image processing.** Installed Next.js 14.2.35 and sharp 0.33.5 matched known advisories. Updated to Next.js 16.4.2 and sharp 0.35.5, refreshed PostCSS and test tooling, adapted async route parameters, and retained the webpack build. AVIF output is disabled. [Next.js support policy](https://nextjs.org/support-policy) and [upstream image optimization advisory](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4).
2. **Unrestricted contact forwarding.** The original endpoint forwarded arbitrary form fields without validating name, email, message, origin, or size. It now enforces same-origin browser submissions, supported encodings, a streamed 16 KiB body limit, field limits, a honeypot, server-controlled forwarding fields, and a 10-second provider timeout. Provider details are not returned to visitors. No live email was sent.
3. **Mobile menu behavior.** Replaced the custom overlay with native dialog focus handling. Escape closes it and restores focus; same-page anchor clicks and desktop resizing also close it. Background scroll is restored.
4. **Content and keyboard access.** Added a skip link, main landmarks that accept focus, current-page navigation, a useful 404, and navigation/content fallbacks when JavaScript is disabled. Hero and reveal content are visible in server HTML. Decorative brand icons and the rotating duplicate phrase no longer clutter screen-reader output.
5. **Guide discovery.** Shortened the guide hero and redundant second heading. At 390 × 844, the first guide begins at approximately 754 px, compared with 1,262 px on the live site: about 508 px earlier. All 26 guides remain listed. This is a layout comparison, not a conversion measurement.
6. **UI polish.** Enlarged navigation and social-link tap targets, restored the name beside the mobile logo, added a direct project CTA, simplified contact copy, and scoped footer rules so article-card footers are not affected by the global footer layout. Checked layouts from 320 to 1,440 px.
7. **Rendering overhead.** Reduced continuously animated stars from 90 to 36, limited mobile decorative icons, capped reveal staggering, replaced three static accent-font weights with one variable font, and removed an unused mono weight. OpenGraph generation now runs statically on Node instead of dynamically at the edge. Vercel-specific analytics scripts are not requested by a local production preview.
8. **Guide path boundary.** Guide lookup now accepts only exact Markdown filenames in the content directory before constructing a filesystem path. Repository-authored HTML remains a trusted content source.

## Remaining work and limits

- Deploy and repeat HTTP, navigation, image, and analytics checks on the actual domain. This checkout does not establish the exact framework version currently deployed.
- Remaining production moderate entries concern Markdown build tooling. Remaining high development entries originate in Tailwind 3's glob/watcher dependencies. The current registry reports no patched braces release; blindly forcing Tailwind 4 or overriding incompatible transitive majors would change the styling pipeline. No forced overrides were applied.
- The CSP intentionally permits inline hydration scripts and Motion styles to preserve static caching. It blocks inline script attributes, object embedding, framing, and unauthorized resource origins, but is a baseline policy rather than strict nonce/hash-based XSS protection.
- Same-origin checks and a honeypot are not rate limiting or bot authentication. The retained, currently unused form endpoint still needs hosting/provider abuse controls before exposing a public form. The visible site continues to use direct email/telephone links. Actual email delivery remains unverified without a configured provider.
- Next.js 16 accepts the existing React 18 integration but emits a deprecation warning. A coordinated React/Motion update should precede Next.js 17.
- No booking service, advertising credentials, replay tool, account dashboard, or revenue model was configured.
